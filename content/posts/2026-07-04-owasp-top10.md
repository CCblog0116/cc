> **OWASP** (Open Web Application Security Project) is a nonprofit foundation that publishes the industry-standard **Top 10** — a list of the most critical web application security risks. It bridges the gap between high-level concepts and hands-on technical work, making it the perfect stepping stone into technical security.

---

## 1. The OWASP Top 10 Is a Baseline, Not a Ceiling

The OWASP Top 10 is a document that lists the ten most common and impactful **web application security risks** (Web 应用安全风险). It is built from data submitted by security teams, consultants, and tool vendors across the industry. The list is updated every few years, with the latest version published in 2021.

> 中文简释：OWASP Top 10 是一份"风险榜单"，告诉你最常见的 10 类 Web 应用漏洞。它不是全部，但是最应该优先修的。

### The 2021 OWASP Top 10

| Rank | Risk | Plain-Language Meaning | Key Risk |
|------|------|------------------------|----------|
| A01 | **Broken Access Control** (失效的访问控制) | Users can access data or functions they shouldn't | IDOR, privilege escalation |
| A02 | **Cryptographic Failures** (加密机制失效) | Sensitive data is exposed or poorly encrypted | Weak ciphers, no TLS, plaintext storage |
| A03 | **Injection** (注入) | Untrusted data is sent to an interpreter | SQL injection, XSS, command injection |
| A04 | **Insecure Design** (不安全设计) | Security was never part of the design | Missing threat modeling, unsafe flows |
| A05 | **Security Misconfiguration** (安全配置错误) | Default settings, verbose errors, open ports | Unnecessary features, exposed stack traces |
| A06 | **Vulnerable and Outdated Components** (易受攻击和过时的组件) | Using libraries or frameworks with known CVEs | Unpatched dependencies |
| A07 | **Identification and Authentication Failures** (身份识别与认证失效) | Weak login, session, or credential handling | Credential stuffing, weak passwords |
| A08 | **Software and Data Integrity Failures** (软件与数据完整性失效) | Untrusted updates or CI/CD pipelines | Insecure deserialization, supply chain attacks |
| A09 | **Security Logging and Monitoring Failures** (安全日志与监控失效) | No visibility into attacks or breaches | Delayed detection, no incident evidence |
| A10 | **Server-Side Request Forgery (SSRF)** (服务器端请求伪造) | Server tricked into making requests to internal systems | Access to cloud metadata, internal APIs |

> 中文简释：2021 版把"安全配置"和"脆弱组件"提得很高，因为真实攻击中漏洞利用链往往从这类"低垂果实"开始。

## 2. Why the Top 10 Matters for AppSec Teams

**Application security** (AppSec / 应用安全) teams use the OWASP Top 10 as a starting point for several activities: building secure coding standards, configuring automated scanners, designing security training, and prioritizing **remediation** (修复) work.

The list does not replace a full **threat model** (威胁模型) or **penetration test** (渗透测试), but it provides a common language between developers, security engineers, and auditors. When a developer says "this is an A03 injection issue," everyone knows roughly what class of risk is being discussed.

> 中文简释：它是一套"通用语言"，让开发、安全、审计快速对齐风险等级。

---

## 3. From Categories to Real-World Exploits

Each Top 10 item is a *category*, not a single bug. For example:

- **A03: Injection** includes **SQL injection** (SQL 注入), **NoSQL injection**, **OS command injection**, and **LDAP injection**.
- **A01: Broken Access Control** includes **IDOR** (Insecure Direct Object Reference / 不安全的直接对象引用), **path traversal**, and forced browsing.
- **A08: Software and Data Integrity Failures** includes **insecure deserialization** (不安全的反序列化) and supply chain attacks like the **SolarWinds** incident.

Understanding the category helps you recognize the *pattern* of failure, even when the exact payload or framework changes.

> 中文简释：学 OWASP 不是背 10 个名字，而是理解每类漏洞的"攻击模式"，看到代码时能识别风险。

---

## 4. How OWASP Defines Risk

OWASP ranks risks by a formula that considers:

- **Exploitability** (可利用性): How easy is it to attack?
- **Prevalence** (普遍性): How common is the weakness in real applications?
- **Detectability** (可检测性): How easy is it for defenders or tools to find?
- **Impact** (影响): How bad is it if successfully exploited?

This is why a bug like SSRF (A10), which is more "technical" and less common than XSS, still made the list: its impact can be severe in cloud environments where metadata services expose credentials.

> 中文简释：排名不是按"名气"，而是按实际可利用性、普遍性和影响综合评估。

---

## 5. Mapping the Top 10 to Defense Controls

For each risk category, OWASP and related projects provide recommended **security controls** (安全控制) and **countermeasures** (缓解措施):

| OWASP Category | Primary Defense |
|----------------|---------------|
| A01 Broken Access Control | **Deny by default** (默认拒绝), enforce authorization on every request |
| A02 Cryptographic Failures | Use strong, modern **encryption** (加密) and TLS 1.2+ everywhere |
| A03 Injection | Parameterized queries, input validation, **output encoding** (输出编码) |
| A04 Insecure Design | Threat modeling and secure design reviews |
| A05 Security Misconfiguration | Harden defaults, disable unused features, automated configuration scanning |
| A06 Vulnerable Components | **SBOM** (Software Bill of Materials / 软件物料清单) and dependency scanning |
| A07 Auth Failures | MFA, strong password policies, secure session management |
| A08 Integrity Failures | Sign commits, verify packages, protect CI/CD pipelines |
| A09 Logging Failures | Centralized logging, alerting, and **SIEM** (Security Information and Event Management / 安全信息与事件管理) integration |
| A10 SSRF | Whitelist outbound hosts, disable unused URL schemes, enforce network segmentation |

> 中文简释：每类风险都有对应控制措施。甲方工作很大程度上就是把这些控制落实到 SDL、扫描器和基线里。

---

## 6. Beyond the Top 10: OWASP Proactive Controls and ASVS

The Top 10 is a *risk list*, not a *secure coding standard*. For that, OWASP publishes the **OWASP Proactive Controls** (主动控制) and the **ASVS** (Application Security Verification Standard / 应用安全验证标准).

- **Proactive Controls**: Lists 10 controls to build in from the start, such as secure data handling, parameterized queries, and logging.
- **ASVS**: A detailed checklist of security requirements organized by verification level (Level 1, 2, 3). It is often used as the basis for security requirements in contracts and audits.

> 中文简释：想从"知道风险"进阶到"落地标准"，必读 Proactive Controls 和 ASVS。

## 甲方视角思考

- OWASP Top 10 是安全团队与研发沟通的最小公分母，把它变成内部 SDL 检查点最有效。
- A06 和 A08 近年上升明显，供应链安全和依赖治理已经从"加分项"变成"必选项"。
- 不要只关注 A03 注入类漏洞，A04 不安全设计才是更难修复但影响更深的根因。
- 把 Top 10 和 ASVS 结合使用，才能从技术风险真正过渡到安全需求管理。
